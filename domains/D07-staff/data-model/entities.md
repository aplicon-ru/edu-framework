# D07 — Модель данных (платформонезависимая)

Статус: черновик первого среза. Описывает ядро домена персонала. Подробная проработка
профстандартов, квалификации, аттестации и трудовых отношений — в дорожной карте.

---

## 1. Сущности

### 1.1 Работник

Роль физического лица в трудовых отношениях с ОО. Возникает по приказу о приёме, прекращается
по приказу об увольнении. Не совпадает с физлицом (роль ≠ человек) и не совпадает с
должностью (могут быть несколько работников на одной должности через доли ставок).

| Атрибут | Описание |
|---|---|
| id | Идентификатор работника |
| fizlitso_id | Ссылка на физлицо (то же, что D05 использует для обучающегося) |
| tabelnyy_nomer | Табельный номер |
| status | принят / уволен / в отпуске / декрет |
| data_priyoma | Дата приёма |
| data_uvolneniya | Дата увольнения (пусто, если активен) |

**Инвариант:** одно физлицо может иметь несколько записей «Работник» одновременно
(разные ОО, разные должности внутри одной ОО, совместительство).

### 1.2 Должность

Единица штатного расписания с квалификационными требованиями. Может быть вакантной.

| Атрибут | Описание |
|---|---|
| id | Идентификатор |
| naimenovanie | Например: «Доцент», «Преподаватель», «Заведующий кафедрой» |
| podrazdelenie_id | Ссылка на подразделение |
| stavok_vsego | Число ставок по штатному расписанию |
| profstandart | Ссылка на профстандарт (если применим) |
| kvalif_trebovaniya | Требования: образование, стаж, категория |
| kategoriya | ППС / АУП / УВП / прочий персонал |

### 1.3 Подразделение

Организационная единица иерархии ОО.

| Атрибут | Описание |
|---|---|
| id | Идентификатор |
| naimenovanie | Название |
| tip | ректорат / факультет / кафедра / деканат / отдел / служба |
| roditel_id | Родительское подразделение (иерархия) |
| rukovoditel_id | Руководитель (ссылка на работника) |

Типовые модели подразделений для ВО, СПО, ДПО — в
[best-practices/typical-org-structure.md](../best-practices/typical-org-structure.md).

### 1.4 Назначение (Работник × Долж­ность)

Связь «многие-ко-многим во времени» — работник может занимать несколько должностей, на
одной должности может быть несколько работников (через доли ставок).

| Атрибут | Описание |
|---|---|
| rabotnik_id | Ссылка |
| dolzhnost_id | Ссылка |
| dolya_stavki | 1.0 / 0.5 / 0.25 и т.п. |
| tip | основное / совместительство внутреннее / совместительство внешнее / почасовое |
| s | Начало действия |
| po | Конец (пусто — действует) |
| prikaz_id | Ссылка на документ-основание |

### 1.5 Квалификация работника (планируется)

Атрибут работника: образование, стажи, категории, повышения квалификации. Требует
проработки против профстандартов.

### 1.6 Нагрузка ППС (агрегат из D14)

Не самостоятельная сущность, а **вычисляемый агрегат** из запланированных занятий D14 в
разрезе преподавателя и периода. D07 читает — не хранит.

| Атрибут | Описание |
|---|---|
| rabotnik_id | Ссылка |
| uchebnyy_period | Ссылка на D14 |
| chasy_po_vidam | лекции / практики / семинары / консультации / … |
| istochnik | ссылка на запланированные занятия D14 |

## 2. Инварианты

1. **Работник ≠ физлицо.** У одного физлица может быть несколько «Работников» одновременно.
2. **Должность может быть вакантной.** Квалификационные требования — на должности, не на
   работнике.
3. **Назначение — М:N во времени.** Один работник может занимать несколько должностей;
   одна должность — с несколькими работниками через доли ставок.
4. **Плановая нагрузка вычисляется, не хранится.** Первичны запланированные занятия D14;
   нагрузка — агрегат.
5. **Изменение назначения — только приказом.** История сохраняется через `s`/`po` и ссылку
   на документ.

## 3. Контракты с другими доменами

### D07 ← D01: нормативная база

D07 подчиняется ТК РФ (трудовые отношения, рабочее время, дисциплина) и профстандартам
(квалификация). Не дублирует их в модели данных — читает как справочники.

### D07 ↔ D06: квалификационные требования к дисциплинам

D06 (учебный план) знает, какая дисциплина требует какой квалификации преподавателя. D07
знает, какой работник какой квалификацией владеет. Стык — при назначении преподавателя
на занятие в D14.

### D07 ← D14: нагрузка

D14 (расписание) — источник плановой нагрузки. D07 читает агрегат из D14; собственной
записи «нагрузка» в D07 нет.

### D07 → D09: фонд оплаты труда

D07 поставляет D09 данные для расчёта: должность, доля ставки, категория, надбавки,
фактическая нагрузка. Расчёт и выплаты — в D09.

### D07 → D02: укомплектованность

D07 предоставляет D02 сведения об укомплектованности штата квалификационными кадрами —
для подтверждения лицензионных требований.

## 4. Дорожная карта

- Развернутая проработка Квалификации работника, механики аттестации, категорий.
- Профстандарты как машиночитаемая онтология (стык с D06 и standards/).
- Стаж педагогической работы — учёт с исключениями (аналогично таймеру задолженности D04).
- Дисциплинарные взыскания работников (ТК РФ ст. 192 — уже разведено с D05: ФЗ-273 ст. 43
  для обучающихся).
- Процессы D07-P01, D07-P02, D07-P03 (см. CHANGELOG).
