# D06-P02: Актуализация ОПОП — новая версия нормы

**Домен:** D06 · **Применимость:** ВУЗ, СПО, Аспирантура
**Статус:** draft

## Назначение

Внести изменение в норму, не разрушая историю: при изменении любого компонента (новый ФГОС,
правка РПД, обновление матрицы) рождается новая Версия ОПОП, действующая вперёд. Уже
пристёгнутые когорты доучиваются по своей версии — их норма не меняется.

## Нормативное основание

- ФЗ-273, ст. 11 — изменение ФГОС как основание актуализации.
- ФЗ-273, ст. 12 — поддержание ОП в актуальном состоянии.
- Профстандарты — изменение требований к ПК.

## Входы

- Действующая Версия ОПОП (база для следующей).
- Основание изменения: новый ФГОС, изменённый профстандарт, приказ, правка РПД/ФОС/плана.

## Шаги

1. Зафиксировать основание (`osnovanie`): что именно вызвало изменение.
2. Создать изменённые версии компонентов (новый учебный план / РПД / ФОС / матрица). Старые
   версии компонентов остаются неизменными — на них могут ссылаться действующие версии.
3. Собрать новую Версию ОПОП: снимок ссылок с обновлёнными компонентами; номер только
   возрастает; задать `deystvuet_s`.
4. При смене ФГОС — переимпортировать УК/ОПК и сверить объём с новым стандартом.
5. Утвердить новую версию (`utverzhdenie_id`) → действует с указанной даты.
6. **Привязки существующих наборов не трогаются** — когорты доучиваются по своим версиям.
   Новые наборы пинятся к актуальной версии приёмной кампанией.

## Особый случай: переутверждение без изменений

Ежегодное переутверждение ОПОП без правки компонентов — это **новое** `utverzhdenie_id`, но
**та же** логическая версия. Новая версия не создаётся (нет изменения компонента).

## Выходы / артефакты

- Новая Версия ОПОП (действует вперёд), старые версии неизменны.
- Обновлённые версии компонентов.
- Документ утверждения.

## Участники

| Роль | Действие |
|---|---|
| Кафедра | Готовит изменённые компоненты |
| Учебно-методическое управление | Сверяет с новым ФГОС/профстандартом |
| Учебно-методический / учёный совет | Утверждает новую версию |

## Типовые ошибки

- Правка утверждённой версии вместо создания новой — нарушение неизменяемости (инвариант 3).
- Перецепление существующих наборов на новую версию — когорта должна доучиваться по своей.
- Новая версия создаётся по календарю без реального изменения компонента — версия рождается
  только по изменению.
- При смене ФГОС объём не пересверен — нарушение инварианта 4 для новой версии.
