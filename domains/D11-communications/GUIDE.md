# D11 · Руководство по работе с доменом

## С чего начать

1. Прочитайте [`standards/sveden/README.md`](../../standards/sveden/README.md) —
   там описан словарь микроразметки и каноническая схема данных.
2. Сведите данные организации в модель по
   [`standards/sveden/schema/instance.schema.yaml`](../../standards/sveden/schema/instance.schema.yaml).
   Большая часть полей уже есть в других доменах (D02, D05, D06, D07, D09) — D11 их
   не создаёт заново, а проецирует.
3. Пройдите по 14 подразделам [`vocab/base.yaml`](../../standards/sveden/vocab/base.yaml)
   и выполните D11-P01.

## Применимость подразделов: как решать «применим / не применим»

Структура раздела `/sveden/` фиксирована приказом **целиком** — её нельзя сократить.
Вопрос «применим ли подраздел» влияет только на то, **чем он будет заполнен**:

| Подраздел неприменим по существу | Что публикуется |
|---|---|
| `grants` (стипендии) для ДПО без бюджетных мест | Поля «отсутствует», структура страницы сохраняется |
| `inter` (международное сотрудничество) без договоров | «отсутствует» |
| `catering` (питание) для онлайн-ДО | «отсутствует» |
| `eduStandarts` (ФГОС) для ДПО, работающего по профстандартам | `eduFedDoc` → «отсутствует», но `eduStandartTreb` (требования профстандарта) — заполняется при наличии |

## За пределами `/sveden/`: остальные обязательные блоки сайта

У вуза есть ещё 15 обязательных публичных блоков сайта помимо `/sveden/`
(противодействие коррупции, СОУТ, политика ПДн, диссоветы, приёмная кампания,
антитеррор — открытый слой, и т.д.) — каждый со своим правовым основанием,
условием применимости и триггером обновления. Каталог — в
[site-requirements-registry.md](site-requirements-registry.md). Это пока справочник,
не процесс: D11-P01 описывает ведение только `OO-01`/`sveden`; для остальных
блоков процессы ещё не написаны.

## Частый вопрос: site = D11 или D12?

D12 «Цифровая инфраструктура» отвечает за **техническую платформу**: хостинг, домен,
интеграции с ГИС, доступность 24/7. D11 отвечает за **содержание и разметку**
конкретного обязательного раздела сайта. Сайт целиком (включая разделы вне `/sveden/`)
может управляться через D12 как инфраструктурный объект; раздел `/sveden/` как
нормативное обязательство — предмет D11.
