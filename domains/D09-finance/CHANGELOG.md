### Уточнено — терминология и связь трёх задолженностей (после разбора экосистемы)

**§4 Стык с академическим контуром** — добавлено терминологическое разведение:
- «Академическое событие» в D09 = **приказ D05** (документное событие)
- НЕ путать с «учебным событием» D04 (генератор обязательств: занятие, экзамен)
- Финансовое обязательство порождается **административным** событием D05, а не
  **учебным** событием D04
- Ссылка на D04/GUIDE.md «Два слоя понятия «событие»»

**§2 Сущности** — новый подраздел «Три задолженности — одна мета-механика»:
- Дисциплинарная (D04) — из учебных событий внутри дисциплины
- Академическая (D04) — из аттестационных учебных событий уровня программы
- Финансовая (D09) — из административных событий D05 (приказов)
- Единая мета-механика: событие → обязательство → запись
- Разные источники событий у каждого вида
- Оказанный объём D04 → D09 — только для расчёта возврата при расторжении,
  не для запуска начислений

### Архитектурное решение: цена в приложении

**Цена фиксируется в приложении к договору, не в теле.** Тело неизменно (услуга, стороны,
общие условия); приложение с графиком платежей версионируется отдельно. Допсоглашение
при изменении цены = новое приложение, без изменения тела. Слепок шаблона фиксируется
на версию плана v1 (момент подписания).

### Открытые вопросы

1. **Уведомления (уровень 4).** Триггеры, которые требуют проработки отдельным процессом:
   договор не подписан в срок; необходимо подписать допсоглашение (смена цены); приближается
   срок платежа; оплата просрочена; финансовая задолженность сформирована. Адресаты:
   деканат, обучающийся, плательщик.
2. **Маткапитал и образовательный кредит — статус ожидания.** Текущая модель имеет
   «Ожидаемое поступление» (подавляет санкции). Открыт вопрос: нужен ли отдельный
   подстатус (одобрен / ожидаем перечисления / отказ) или достаточно пометки источника.
