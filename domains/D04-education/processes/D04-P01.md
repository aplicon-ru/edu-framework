# D04-P01: Учебное событие — от генерации обязательств до факта

**Домен:** D04 · **Применимость:** ВУЗ, СПО, ДО, ДПО, Аспирантура
**Статус:** draft

## Назначение

Описывает базовый цикл учебного процесса: как событие порождает обязательства для каждого
участника, как они закрываются записями, как черновое присутствие затвердевает в неизменяемый
факт. Это центральный цикл академического контура — все остальные процессы (задолженность,
ведомость, зачётка) вытекают из него.

## Нормативное основание

- ФЗ-273, ст. 58 — промежуточная аттестация обучающихся.
- ФЗ-273, ст. 43 — права и обязанности обучающихся (посещаемость, дисциплинарная ответственность).

## Входы

- Расписание / план-график практики (определяет состав события).
- Учётная политика (размер буфера затвердевания, веса форм контроля).
- Данные о составе учебной группы из D05 (черновой список).

## Шаги

1. Событие начинается → система вычисляет **черновой** состав («кто должен быть» по
   расписанию и данным D05). Состав — это будущий факт присутствия, не проекция группы.
2. Для каждого участника порождается пучок **независимых** обязательств по формам контроля,
   привязанным к событию (дисциплинарное + содержательные). Для аттестационного события пучок
   может покрывать несколько дисциплин (профмодуль СПО).
3. Каждое обязательство закрывается своей записью. Закрытость вычисляется (есть положительная
   запись), не переключается флагом. Отработки и пересдачи — новые записи, не правки.
4. По истечении технологического буфера (политика, например 3 дня) черновой состав
   затвердевает в исторический факт. Внутри буфера изменения — обновление чернового; после
   буфера — только сторно документом-основанием.
5. Перед сессией кафедра закрывает модуль → фиксируется снимок рейтинга текущего контроля.
   До закрытия — живой агрегат; после — факт, меняется только корректирующей ведомостью.

## Особые сценарии

**Отмена события:**
- Внутри буфера: черновые обязательства аннулируются бесследно, событие = «не состоялось».
- После затвердевания: сторно документом-основанием.

**Частные случаи события:**
- **Занятие**: свидетель = валидатор = преподаватель; присутствие в аудитории/на вебинаре.
- **День практики**: свидетель — база/СКУД/скан журнала практики; **валидирует кафедра**
  (разделение критично: защита от подлога через самовалидацию).
- **Аттестационное событие**: пучок по 1..N дисциплинам; режим — независимые записи или
  единая оценка, размноженная по пучку (профмодуль).

## Выходы / артефакты

- Обязательства (черновые → факт) по каждому участнику.
- Записи (первичные / отработки / сторно) с указанием валидатора.
- Снимок рейтинга текущего контроля (при закрытии модуля).

## Участники

| Роль | Действие |
|---|---|
| Преподаватель / Свидетель | Фиксирует присутствие и первичные результаты |
| Валидатор | Удостоверяет факт (всегда человек); при практике — кафедра |
| Кафедра | Закрывает модуль снимком перед сессией |
| УМУ (учебно-методическое управление) | Контролирует корректность ведомостей |

## Типовые ошибки

- Прямая правка записи вместо «сторно + новая запись» — нарушение неизменяемости факта.
- Самовалидация при практике (студент сам вносит и удостоверяет) — уязвимость.
- Начисление баллов за отработку пропуска — отработка снимает дисциплинарное обязательство
  (допуск), но не восстанавливает баллы БРС за присутствие.
