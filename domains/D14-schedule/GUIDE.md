# D14 · Руководство по работе с доменом

## Как определить, что изменение относится к D14

D14 — **разворачивание плана в календарь и ресурсы**. Не сам план (это D06) и не
факт проведения (это D04).

| Ситуация | Домен |
|---|---|
| Методист добавил в РПД модульный контроль темы 3 | D06 (план события) |
| Расписание поставило пару на 15.10.2026 в ауд. 301 | D14 (слот) |
| Студент нажал «Отметиться» на слоте | D14 (регистрация) |
| Педагог нажал «начать занятие», система создала журнал | D14 → D04 (слот → факт) |
| Педагог выставил оценки в журнале | D04 (запись) |
| Кафедра перенесла пару на другой день | D14 (перенос слота; события D06 не пересоздаются) |
| Педагог посчитал свою нагрузку за семестр | D07 читает агрегат D14 |

Правило: если меняется **план учебных событий** (что должно произойти) — это D06.
Если меняется **развёртка на календарь** (когда и где) — это D14. Если фиксируется
**факт** (что произошло) — это D04.

## D14 vs D04

| Вопрос | D14 | D04 |
|---|---|---|
| Что должно произойти? | ссылка на план D06 | — |
| Что происходит сейчас (регистрация → идёт)? | ✓ | — |
| Что произошло (записи, оценки)? | — | ✓ |
| Кто должен быть на слоте? | ✓ (именованный отбор) | — |
| Кто был (снимок факта)? | — | ✓ (после перехода слота в идёт) |
| Нагрузка преподавателя? | ✓ (агрегат) | — |

## Именованный отбор: правило поверх D05.Группа

Отбор — не дубль группы D05, а **правило** поверх неё. D05 уже владеет сущностью
`Группа` с типом (основная / подгруппа / поток / элективная) и связью
`Членство в группе` (M:N во времени). Именованный отбор ссылается на одну или
несколько групп D05 и говорит: «состав слота = объединение активных членств в этих
группах на дату слота, с фильтром».

**Хранится:** имя, срок действия, правило (какие группы D05, какой фильтр).
**Не хранится:** результат вычисления (состав обучающихся). Он вычисляется при
переходе слота в «идёт» против актуальных `D05.Членство в группе` и замораживается
в D04.

## Регистрация — процесс уровня слота, не события

Одна регистрация на слоте покрывает **все** учебные события внутри. У каждого
события — свой состав через `assignment_mode` формы контроля (`all` / `per_student`),
но регистрация как факт присутствия — общая для слота.

Пример:
- Слот содержит «занятие по D» (assignment_mode: all) и «модульный контроль темы 3»
  (assignment_mode: per_student, только у 22 из 25)
- Обучающийся отметился на слоте один раз → присутствие зафиксировано
- Для «занятия по D» — обязательство присутствия открыто у всех 25
- Для «модульного контроля» — обязательство сдачи открыто только у 22

## Типовые ошибки

**Заводить события прямо в D14.**
Ошибка: расписание создаёт новую сущность «модульный контроль» при постановке слота.
Правильно: модульный контроль как запланированное событие живёт в РПД (D06), D14
только назначает ему время и ресурсы через слот.

**Дублировать D05.Группа именованным отбором.**
Если у D05 уже есть группа с явным составом (например, «электив-философия» типа
«элективная»), не создавайте отдельный отбор с тем же составом — просто ссылайтесь
на группу D05. Отбор нужен там, где состав получается **комбинацией** групп или
требует **фильтра**.

**Хранить в отборе снимок состава.**
Отбор хранит правило, не состав. Снимок замораживается в D04 при переходе слота в
«идёт».

**Регистрация на каждое событие внутри слота.**
Ошибка: заставлять обучающегося отмечаться отдельно на «занятие» и «модульный
контроль». Правильно: одна регистрация на слоте, состав каждого события
определяется через `assignment_mode` его формы контроля.

**Смешивать перенос и редактирование.**
Перенос слота — это пара событий (исходный → «перенесено», новый → «запланировано»).
Не редактирование даты в существующей записи: это скрывает историю. Учебные
события D06 остаются теми же — переносится их развёртка.

**Считать нагрузку из факта D04, а не из плана D14.**
Нагрузка ППС — плановый показатель, считается из слотов D14. Фактическое проведение
(D04) может отличаться от плана; для учёта отработок — отдельный процесс.

## Что делать при отмене слота

1. Перевести слот в состояние «перенесено» (без замены) или «завершено с признаком
   не состоялся».
2. Учебные события D04 не создаются (если слот отменён до перехода в «идёт»).
3. Если слот уже стартовал (D04 создан) — отмена оформляется сторно в D04
   (academic-concept v1.4 §4.4 «событие-отмена»).
4. Запланированные учебные события D06 остаются — их можно развернуть на другом
   слоте позже.
5. Нагрузка пересчитывается автоматически.
