# «Сведения об образовательной организации» — словарь микроразметки sveden

Этот раздел содержит машиночитаемое описание раздела официального сайта ОО
**«Сведения об образовательной организации»** (`/sveden/...`) — структуру
подразделов, обязательные поля и микроразметку `itemprop`, которой должна
быть размечена каждая страница.

---

## Зачем это нужно

Раздел сайта `/sveden/` — не просто страница «о нас». Это **проверяемый ГИС-артефакт**:
АИС «Мониторинг» Рособрнадзора обходит сайт ОО как робот и сверяет наличие
каждого обязательного поля с микроразметкой `itemprop` из Метод. рекомендаций.
Несоответствие — основание для предписания и штрафа (до 100 000 ₽).

Словарь `vocab/base.yaml` даёт:
- единый источник истины для генерации `/sveden/` из канонических данных ОО
  (`org`, `programs`, `staff`, `infra`, `docs` — см. `schema/instance.schema.yaml`)
- проверку «всё ли размечено» до публикации, а не после визита проверяющего
- согласованность данных между сайтом, лицензионным пакетом (D02) и другими
  проекциями одной модели организации

## Принцип «append-only»

Наблюдение: каждый новый приказ Рособрнадзора **добавляет** подразделы и поля,
но не меняет смысл старых тегов `itemprop`. Поэтому словарь устроен слоями:

- `vocab/base.yaml` — стабильное ядро по действующей версии Метод. рекомендаций
  (сейчас v9.0.0). Не переписывается при выходе новой редакции.
- Будущие дельты приказов (`vocab/v<N>.yaml`) добавляют новые подразделы/поля поверх
  базового слоя. Действующий словарь = `base` ⊕ применимые дельты.

Миграций нет: старая разметка не ломается новой версией приказа.

## Формат записи подраздела

```yaml
common:
  url: "/sveden/common"        # обязательный URL подраздела (фиксирован приказом)
  a11y: "copy"                 # требуется версия для слабовидящих
  status: "verified"           # verified | TBD — сверено ли с Метод. рекомендациями
  source: "Метод.рек. v9.0.0, Табл.3.2.1"
  fields:                       # одиночные поля → itemprop
    fullName: { itemprop: "fullName", from: "org.full_name" }
  groups:                        # повторяющиеся блоки (главный тег на коллекцию)
    uchredLaw:
      itemprop: "uchredLaw"
      from: "org.founders[]"
      fields:
        nameUchred: { itemprop: "nameUchred", from: "founder.name" }
```

`from:` — путь к данным в канонической модели организации (`schema/instance.schema.yaml`).
`from: "TBD"` — поле задокументировано Метод. рекомендациями, но путь в схеме данных ещё
не согласован; предложение — в комментарии рядом. Не «угадывайте» пути — оставляйте `TBD`.

Пустое обязательное поле на рендере выводится как «отсутствует» (или «нет»), а не
пропускается — это требование `_global.yaml` → `rules.missing_value`.

## Как использовать

1. Заполните каноническую модель данных организации по `schema/instance.schema.yaml`.
2. Сгенерируйте (или разметьте вручную) страницы `/sveden/<slug>/` по `vocab/base.yaml`:
   для каждого поля — элемент с атрибутом `itemprop`, значение — из `from:`.
3. Для пустых обязательных полей выведите текст «отсутствует» (см. `_global.yaml`).
4. Добавьте версию для слабовидящих (`a11y: "copy"`) на каждую страницу подраздела.
5. Сверьте результат через АИС «Мониторинг» Рособрнадзора.
