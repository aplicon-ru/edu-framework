# Дидактикон

**Дидактикон** — PWA-ЭИОС (электронная информационно-образовательная среда) поверх
1С:Univerkon. Тонкий студенческий контур: проекции + плеер контента + клиент локального
экзамена. Всё состояние живёт в Univerkon, но между ним и студентом — LRS-буферы для
устойчивости к недоступности ядра.

> ⚠ Карточка создана из разбора концепций `2026-07-06-concept-eios.md` и
> `2026-07-06-didakticon-block3-event-lifecycle.md`. Ссылка на репозиторий требует
> уточнения от автора.

## Ключевые архитектурные решения

Из `concepteios.md`:

1. **Univerkon — единый источник фактов и идентичности; вне горячего пути.** Запись
   прогресса и чтение проекций не зависят от мгновенной доступности 1С.
2. **Решение — единый источник, активность — распределяема.** Состояние, влияющее на
   допуск и права, — только в Univerkon. Прохождение и телеметрия — асинхронно.
3. **Машина — только свидетель.** Факт рождает человек-валидатор. Технический носитель
   порождает лишь свидетельство. См. D04 GUIDE.md «Два слоя понятия событие».
4. **Контент — лист, не структура.** SCORM/cmi5-курс — ресурс, привязанный к
   дидактической единице; иерархию держит Univerkon.
5. **Фронт — только студенческий.** Преподаватель и валидатор работают в родном
   интерфейсе Univerkon. Дидактикон не дублирует журнал и проведение ведомостей.

## Слои реализации

| Слой | Что | Где |
|---|---|---|
| Ядро фактов + идентичности | Univerkon (см. `univerkon.md`) | 1С |
| Контент | Статические SCORM/cmi5-пакеты | Хостинг / CDN |
| Слой активности | Живой черновой свидетель: телеметрия прохождения, буфер устойчивости | Отдельный лёгкий LRS |
| Студенческий ЛК | Тонкий PWA: проекции + плеер + клиент локального экзамена | Браузер / хостинг |
| Локальная зона аттестации | Внутренний экзаменатор: только из сети ОО, офлайн-способный | Сеть ОО |

## Отступает от edu-framework

Специфика реализации, не являющаяся частью методологии:

- **PWA с IndexedDB / Service Worker / Cache API** — конкретный технологический выбор
- **SCORM 1.2/2004 + cmi5 адаптер** — контентный протокол
- **OIDC + машинные credentials (mTLS, TPM)** — модель аутентификации
- **LRS как отдельный сервис** — паттерн разделения ядра и буфера
- **Локальный экзамен через машинный сертификат станции** — гейт локальности +
  свидетель-credential в одном
- **runtime-пульт педагога с 3 зонами** — UX-специфика

Всё это — реализация, а не методология.

## Обратная связь фреймворку

Реализация Дидактикон даёт edu-framework:

- **Явное состояние «регистрация» в жизненном цикле события** — обогащение D04
- **Классификация форм контроля по трём осям** — уточнение D04
- **Пять фактов формы контроля** — детализация закрытия обязательства (D04)
- **Терминологическое разведение** «пересдача формы» (авто, без approval) vs «отработка
  пропуска» (approval-based)
- **Педагогический бонус** как отдельный механизм, не входящий в пакет и ФОС
- **Пакет занятия как манифест** — концепция для D06
- **Gate как первоклассная сущность** — концепция для D06

## Стратегия сборки (walking skeleton)

Из `concepteios.md`, §9:

1. **Срез 1 — спина насквозь.** OIDC → ЛК → одна дисциплина → один курс → LRS → один
   итог → мост → ведомость → зачётка-view. Один студент, один проход. Прошивает все швы.
2. **Срез 2 — локальная зона.** mTLS-станция, одноразовая ссылка, офлайн-буфер → сверка.
3. **Срез 3 — ширина.** Остальные типы событий, БРС, задолженность.

## Связанные системы

- **1С:Univerkon** (`univerkon.md`) — ядро фактов и OIDC
- **LRS** — отдельный xAPI-сервер для буферизации CMI-коммитов и свидетельств прохождения
  (не описан отдельной карточкой)
