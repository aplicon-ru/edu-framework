# Univerkon (1С)

**1С:Univerkon** — активная реализация академической ИС на платформе 1С:Предприятие.
Единый источник фактов и идентичности (OIDC-провайдер) для экосистемы «Univerkon +
Дидактикон + LRS».

> ⚠ Карточка создана из разбора концепций `2026-07-06-concept-eios.md` и
> `2026-07-06-didakticon-block3-event-lifecycle.md`. Ссылка на репозиторий /
> продуктовую страницу требует уточнения от автора.

## Роль в экосистеме

По концепции ЭИОС (`concepteios.md`):

> **Univerkon — единственный источник фактов и решений, но он не стоит в горячем пути
> учащегося.** Между студентом и ядром лежат буферы, чтобы недоступность 1С не
> останавливала обучение.

- Ядро фактов: траектория, дидактические единицы, события, обязательства, записи,
  ведомости, зачётка
- OIDC-провайдер идентичности
- Валидатор фактов (человек-валидатор всегда работает в родном интерфейсе Univerkon,
  не в Дидактиконе)

## Реализует концепции фреймворка

| Домен | Как реализуется |
|---|---|
| **D04** | Учебное событие как генератор обязательств; ведомости; зачётка как витрина; таймер задолженности с периодами-исключениями |
| **D05** | Контингент, приказы, статусы, траектория; вход через OIDC |
| **D06** | Норма-ось: ОПОП, УП, РПД, ФОС; учебный план и его версии; версия ОПОП для набора |
| **D14** | Расписание — источник запланированных событий; именованные отборы как правило поверх Группа+Членство D05 |
| **D07** | Оргструктура, кадры, профили преподавателей |
| **D09** | Финансы, договоры |
| **D12** | OIDC-провайдер; интеграции с ЕПГУ/ФРДО/ФИС ГИА |

Также реализует концепции, которые эта версия фреймворка **пока не описала** и которые
будут вложены в edu-framework (см. `inbox/2026-07-06-univerkon-ecosystem.memo.md`):

- Пятизвенный жизненный цикл формы контроля (assignment → launch → attempt → submission → evaluation)
- Классы форм контроля по трём осям (role_in_rating / assignment_mode / time_model)
- Двухфазность форм контроля с бинарным принятием
- Разведение «пересдача формы» vs «отработка пропуска»
- Педагогический бонус как отдельный механизм

## Отступает от edu-framework

Различия, характерные для реализации на 1С:

- **Ядро в горячем пути активности отсутствует.** По концепции устойчивости — Univerkon
  вынесен из hot path, между ним и студентом — LRS и PWA-буферы. Это архитектурное
  решение реализации; edu-framework про такие вещи не говорит.
- **Единый OIDC-провайдер идентичности** — методология этого не требует, это выбор
  реализации.

## Обратная связь фреймворку

Из практики Univerkon в edu-framework приходят (или уже пришли):

- Разведение свидетель / валидатор (`witness` / `validator`) — принято в D04
- Расширенный жизненный цикл события (6 состояний вместо упрощённого) — в дорожной карте D04
- Пакет занятия как манифест — концепция для D06 (пакет ≠ контейнер контента)

## Связанные системы

- **Дидактикон** (`didakticon.md`) — PWA-ЭИОС поверх Univerkon (студенческий контур,
  runtime-пульт педагога)
- **LRS** — отдельный лёгкий xAPI-сервер для буферизации прогресса; не описан
  отдельной карточкой (внутренний сервис Дидактикона)
