# Implementations — реализующие фреймворк сервисы и приложения

Каталог внешних систем, которые реализуют одну или несколько концепций из edu-framework:
конкретные домены, процессы, стандарты. Служит двум задачам:

1. **Обратная связь фреймворку.** Реальная реализация — источник практических уточнений
   к модели: где концепция ломается, что упростили, что добавили.
2. **Ориентир для сообщества.** Помогает найти живой пример реализации домена или процесса.

## Структура записи

Один файл на реализацию: `implementations/<slug>.md`. YAML frontmatter — машиночитаемые
атрибуты, тело — описание.

```markdown
---
name: Название системы
url: https://example.com
kind: reference | production | prototype | commercial
status: active | archived
domains:
  - D05
  - D06
processes:
  - D05-P01
  - D06-P01
standards:
  - sveden
maintainer: организация или @username
license: proprietary | MIT | AGPL-3.0 | …
last_verified: 2026-07-04
---

# Название системы

Короткое описание — 2–3 абзаца о том, что делает система, какие концепции фреймворка
воплощает, как соотносится с моделью edu-framework.

## Ключевые связи

- **Реализует:** ссылки на домены и процессы, которые покрыты
- **Расширяет:** что реализовано за пределами фреймворка
- **Отступает:** где реализация отклоняется от концепции edu-framework и почему

## Обратная связь фреймворку

Уроки из практики: что подтвердилось, что уточнили, что предложили изменить в модели.
```

## Атрибут `kind` — жанр реализации

| Значение | Смысл |
|---|---|
| `reference` | Референсная — сделана как показательная реализация концепции; обычно open source |
| `production` | Промышленная — работает в реальных ОО; необязательно open source |
| `prototype` | Прототип — черновая проверка идей; ограниченный функционал |
| `commercial` | Коммерческий продукт — платный, закрытый |

## Атрибут `status`

- `active` — развивается, актуально
- `archived` — заморожено или прекращено; сохраняется для истории

## Атрибуты `supersedes` / `superseded_by`

Для отслеживания преемственности между реализациями:

- **`supersedes: [<slug>, ...]`** — эта реализация заменила перечисленные (обычно `archived`).
- **`superseded_by: [<slug>, ...]`** — эту реализацию заменили перечисленные. Обычно
  проставляется в паре с изменением `status: active → archived`.

Оба поля — списки. Реализация может унаследовать концепции от нескольких предшественников
и быть заменённой на несколько преемников (редко).

## Правила

1. **Только связанные с фреймворком системы.** Не универсальный каталог образовательных ИС.
2. **Указывать связь.** Обязательные поля `domains` и `processes` — какие концепции реализуются.
3. **Отклонения — не порок.** Раздел «Отступает» приветствуется: практика может опережать
   модель или сознательно упрощать.
4. **Не размещать чувствительное.** Реквизиты доступа, внутренние скриншоты с данными ОО, ЛНА
   клиентов — не сюда.
5. **`last_verified`** обновляется при каждом обзоре актуальности (раз в 6 месяцев минимум).

## Обратные ссылки

Каждый домен, у которого есть реализации, содержит в `metadata.yml`:

```yaml
implementations:
  - <slug>          # ссылки на файлы implementations/<slug>.md
```

Обновляется вручную при добавлении новой реализации.
